# レスポンシブ(幅をまたぐ)

読む場面: 複数の幅に対応するとき。条件がない原則はどこでも使い、条件がある原則は当てはまるときだけ使う。

## 原則

### 狭い幅ではデスクトップのUIを縮めるだけで済ませず、1画面に見せる情報と操作を絞って階層的に組み直す〔推奨〕
条件: 幅=狭い ／ 理由: 小さい画面は状態を見失いやすく短時間で使われるため絞り込みが要る(できることは減らさない)。

### 入力手段を端末の種類や画面幅で決めつけず、タッチ・ポインタ・キーボードのどれでも同じ機能を使えるようにする〔推奨〕
理由: マウスの有無は確実に検出できず、利用中に入力手段を切り替える人もいる。

### 画面の広さが変わってもできることは変えず、大きさ・見せる情報の量・部品の表現だけを変える〔推奨〕
理由: 使える領域で機能が増減すると、できることを予測できなくなる。

## チェックリスト

- 狭い幅ではサイドバーを消さず、目次型は詳細から戻れる形に、絞り込み型はメニューやシートに置き換える(条件: 幅=狭い、サイドバーがある画面)
