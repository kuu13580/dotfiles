# ダイアログ・モーダル

読む場面: ダイアログ・モーダル・シート・確認ダイアログを作るとき。条件がない原則はどこでも使い、条件がある原則は当てはまるときだけ使う。

## 原則

### 狭い幅では中央に浮かぶダイアログを避けて下から出る全画面やシートで開き、広い幅と同じく閉じるボタンを見える位置に置く〔推奨〕
条件: 幅=狭い、入力手段=タッチ ／ 理由: 狭い中央ダイアログは窮屈で、下からなら親指が届く(全画面の中に階層は作らないが、閉じる・破棄の短い確認は重ねてよい)。
例: 作成フローは下から出る全画面、確認だけなら画面下に寄せたシートにする。

### 破壊的操作の確認には安全なキャンセルを置くが既定にはせず、赤い破壊的スタイルはユーザーが意図していない破壊的操作に使う〔推奨〕
条件: プラットフォーム=iOS ／ 理由: 逃げ道を用意しつつEnterで反射的に閉じられるのを防ぎ、自分で選んだ操作なら赤で強調を重ねない。
例: 「ゴミ箱を空にする」を選んだ後の確認では、実行ボタンを通常の見た目にする。

### モーダルやシートには見える閉じる手段を置き、キーボードやシステムの戻る操作でも閉じられるようにし、スワイプなどだけに頼らない〔推奨〕
理由: スワイプは気づかれにくく難しい人もいる(外側で閉じるのは内容を失っても困らないときだけ)。

### 特に危険でまれな操作では、通常のクリックとは違う操作で確認させ、反射的な承認を防ぐ〔推奨〕
条件: 重大でまれな破壊的操作 ／ 理由: 通常と違う操作を求めると反射的な承認を防げるが、頻繁に使うと形骸化する。
例: プロジェクトの削除は、プロジェクト名を入力するまでボタンを押せなくする。

### 入力の量で器(ページ・ダイアログ・サイドパネルなど)を選び、手順が多い・複雑・広さが要る作業はモーダルに詰め込まず専用のページにする〔推奨〕
理由: ダイアログは文脈を保てるが狭く割り込みが強く、多段だと元の作業から長く引き離す(狭い幅で下から出す全画面はページとして扱う)。
数値: 目安: 最大サイズのダイアログに収まらない量や、ダイアログ内で複数ステップの移動が要る作業はページにする(Carbon / Atlassian)

### 確認では対象と件数、何が起きるか、取り消せるかを具体的に書き、ボタンは「はい/いいえ」「OK」ではなく操作名にする〔推奨〕
理由: 「よろしいですか?」「OK」は読まずに押され、操作名のボタンなら読み飛ばしても気づける。
例: 「3件のファイルを完全に削除しますか? 取り消せません」+「削除する」「キャンセル」
数値: Apple HIG: アラートのタイトルは2行を超えないようにする

### ポップオーバーは少量の情報や操作に使い、呼び出し元を覆わず、外側を押して閉じても入力内容を失わせない〔推奨〕
理由: 外側を押すと意図せず閉じやすく、そこで入力が消えると作業を失わせる。

### モーダルは終えて元の画面に戻る作業に使い、別の画面へ進む作業や元の画面と行き来・参照しながら進める作業は別のページにする〔推奨〕
理由: モーダルは作業を挟む器で、先へ進む作業には意味がなく、参照しながらの作業は背景を隠して妨げる。

### 元の画面の情報と見比べながら進める作業は、背景を隠すモーダルにせず、元の画面を見たまま操作できるようにする〔推奨〕
理由: モーダル中は他の情報を見られないが、妥当な値の判断には隣の行などを見比べたい。
例: 表の行の詳細や編集は、表を見たまま使えるサイドパネルで開く。

### ボトムシートは背景を見ながら行う短い操作や少量の補足情報に使い、ページ遷移の代わりや長く複雑な内容には使わない〔推奨〕
条件: 機能=ボトムシート ／ 理由: 本来のページをシートで開くと戻るなどの移動が崩れ、長い内容はシートでは読みにくい。
例: 並び順の選択はシートで出し、項目の詳細は画面遷移で開く。

### モーダルの中に階層のある移動を作り込まず、詳細設定のような奥へ進む操作は別の画面やパネルに分ける〔推奨〕
条件: 機能=ダイアログ ／ 理由: モーダル内に階層があると戻り方を見失い、閉じるとどこまで戻るのかも分からない。

## チェックリスト

- ダイアログでの操作は処理が完了するまでダイアログを閉じず、失敗したらダイアログの中で該当箇所とエラーを示す(条件: 機能=ダイアログ)〔必須〕
- ダイアログ内のスクロールは避け、必要なら見出しと操作ボタンを固定して常に見えるようにする(条件: 機能=ダイアログ)
- 破壊的な選択肢を、たとえ最も選ばれそうでもEnterで確定される既定のボタンにしない
- ダイアログのキャンセルや閉じる操作では黙って保存・送信せず、変更がなければ確認を出さずにそのまま閉じる(条件: 機能=ダイアログ)
- 閉じる・破棄・取り消せない操作についての短い確認を除き、モーダルやシートを重ねて開かず、次を出す前に前のものを閉じる
- 段階的に止まるシートは、指を離した位置から近い停止位置に吸着させ、勢いよくはじけば途中を飛ばせるようにする(条件: 機能=ボトムシート)
- 幅でダイアログの見た目を変えても、モーダルかどうかと、外側を押す以外の閉じ方(閉じるボタン・Esc・戻る操作)はすべての幅でそろえる(条件: 機能=ダイアログ)
