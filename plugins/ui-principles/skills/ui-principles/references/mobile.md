# モバイル(狭い幅・タッチ)

読む場面: 狭い幅、タッチ操作。条件がない原則はどこでも使い、条件がある原則は当てはまるときだけ使う。

## 原則

### 主な操作は、親指の届きやすい画面の下寄りに集める〔推奨〕
条件: 幅=狭い、入力手段=タッチ ／ 理由: 片手で持つと、画面の上部には親指が届きにくい。

### ジェスチャーの意味をOSの慣習やアプリ内でそろえ、場所や状態で変えたりシステムのジェスチャーと競合させたりしない〔推奨〕
条件: 入力手段=タッチ ／ 理由: ジェスチャーは常に同じに動くと期待され、場所による違いやOSとの重なりは誤操作を招く。

### ジェスチャーで発動する操作は取り消しやすさで確定のタイミングを変え、取り返しのつかない操作は指を離すまで確定しない〔推奨〕
条件: 入力手段=タッチ、ジェスチャーで操作を発動するとき ／ 理由: 軽い操作は途中の発動で結果が早く見え、重い操作は途中で確定すると気が変わっても戻せない。
例: 検索を開くスワイプは一定距離で発動、画面を閉じるスワイプは指を離すまで確定しない。

### タッチで押す要素は、見た目が小さくても、押せる範囲を指で確実に押せる物理的な大きさ以上にする〔推奨〕
条件: 入力手段=タッチ ／ 理由: 小さい要素は押し損じが増える(フィッツの法則。主要な操作や歩行中はさらに大きく)。
数値: 目安: 一辺約1cm(7〜10mm)以上 / Apple HIG: 44×44pt / Material Design: 48×48dp

## チェックリスト

- ジェスチャーだけに機能を割り当てず(署名など動き自体が目的のものは除く)、見えるボタンやメニューの単純な操作でもできるようにする(条件: ジェスチャーで操作できる機能を作るとき)
- 入力内容に合ったソフトウェアキーボードとEnterキーの表示を出す(条件: 入力手段=タッチ)
- ノッチやホームインジケーターなどのシステム領域で、重要なコンテンツや固定ヘッダ・フッタの操作を隠したり欠けさせたりしない(条件: ノッチやホームインジケーターのある端末)
