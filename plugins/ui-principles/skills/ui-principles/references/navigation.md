# ナビゲーション

読む場面: ナビゲーション・タブ・メニュー・戻る操作を作るとき。条件がない原則はどこでも使い、条件がある原則は当てはまるときだけ使う。

## 原則

### タブは並列で明確に分けられる内容の切り替えに使い、順に読む内容や見比べる内容をタブに分けない〔推奨〕
条件: 機能=タブ ／ 理由: 隠れた内容は見落とされ比較は記憶頼みになる(順序のある内容は見出し付きの1ページに)。
数値: 目安: 固定タブは4つまで、5つ以上は窮屈になる(Material 3)

### 狭い画面でも主要な行き先が少なければナビゲーションを隠さず、多ければ一部を見せて残りを折りたたむ〔推奨〕
条件: 幅=狭い ／ 理由: ナビゲーションを隠すと見つけにくくなり、使われにくい。
数値: 目安: スマートフォンで常に表示する主要な行き先は4〜5個まで(NN/g。別記事では4個以下)

### メニュー項目の並び順を、使用頻度や直前の選択に応じて動的に変えない〔推奨〕
理由: 項目の位置は空間的に覚えられるため、位置が変わると学習できない。

### 主要なセクションを行き来しても、各セクションでの位置・スクロール・タブ・検索の状態を保つ〔推奨〕
条件: 主要なセクションを頻繁に行き来するとき ／ 理由: 戻るたびに初期状態になると作業が失われ、毎回やり直しになる。

## チェックリスト

- ナビゲーションの部品は幅に合わせて切り替え、広い幅では画面下部のナビゲーションバーを使わない
- 一覧から詳細へ移って戻ったときや戻る・進むで移動したときは、元のスクロール位置を復元する
- フィルタ・タブ・ページ番号などの表示状態や移動をURLに反映し、共有・再読み込み・戻る/進むで再現できるようにする(条件: プラットフォーム=Web)
- 戻る操作はユーザーがたどった順に直前の場所へ1段ずつ戻し、ブラウザの戻るを無効にしない
