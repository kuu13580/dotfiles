description: セッションやcompactを跨いでも設計判断が失われないよう、確認した事実と決定を CONTEXT.md に書き出す・読む・追記する。設計が固まったとき、実装中に決定が変わったとき、PR本文を書く前に使用する。「引き継ぎ記録」「決定記録を書いて」「compact前に記録して」「設計を引き継いで」「CONTEXT.md 更新」などの依頼でも発動する。
---

引き継ぎはファイルを主、セッション間メッセージを補助とする。文脈もメッセージも失われうるが、ファイルは残る。

信号 (確認した事実・決定・潰した仮説) とノイズ (探索の経路・一過性の訂正・撤回された指摘) を仕分け、信号だけを残す。

記録があるため、既定ではセッションを分割しない。SessionStart フックが compact を跨いで記録を戻す。

## 引数

`/prepare-context <調査 | 設計 | 実装 | pr>`

引数なしで呼ばれた場合は、会話の内容からフェーズを推測し、**推測結果を宣言してから**書き出す。
英語 (`research` / `design` / `implement` / `pr`) でも受ける。

| フェーズ | 厚くする | 薄くする |
| --- | --- | --- |
| `調査` | 確認した事実 (根拠必須)。未決着なら現在地を手順ごと | 決定 |
| `設計` | 決定と理由、潰した仮説、前提・保留 | 事実は結論のみ |
| `実装` | 決定の変更履歴、実装中に判明した新事実 | 既存の決定の再掲 |
| `pr` | コードから読み取れない設計思想・意思決定 (PR本文の素材) | 実装詳細 |

## 置き場

`~/.claude/contexts/<repo>/<key>/` に2ファイル。キーの解決は `${CLAUDE_PLUGIN_ROOT}/scripts/resolve-key.sh` を実行して得る (自分で組み立てない)。

| ファイル | 役割 | 上限 |
| --- | --- | --- |
| `CONTEXT.md` | 現役の事実・決定・未決着の調査・保留。SessionStart で自動注入される | **400行 / 24KB** |
| `CONTEXT.archive.md` | 撤回・置き換えられた決定と、変えた理由。注入しない | なし |

- キーの優先順位は **`git config --worktree prepare-context.key`（明示）→ ブランチ名**。明示キーを先に見るのは、タスク途中でブランチを切っても記録が孤立しないようにするため
- default branch (`main` / `master` / `develop`) で明示キーも未設定なら `exit 1`。**その場合はキーを何にするかユーザーに尋ねて設定してから書き出す**
- `~/.claude/tasks/` は Claude Code 自身が使用中 (セッションUUID名のディレクトリに `.lock` / `.highwatermark`) のため使わない
- リポジトリ内には置かない。`.gitignore` と PR の diff を汚さず、個人の作業スタイルをリポジトリの規約に混ぜないため
- マージ後など記録が不要になったら、**ユーザーの確認を得てから** ディレクトリごと削除する

上限値の一次情報は `${CLAUDE_PLUGIN_ROOT}/scripts/load-record.sh` の `MAX_LINES` / `MAX_BYTES`。上の表の値と食い違ったらスクリプト側を正とする。

## 書き出す

**形式は任せる。**章立て・順序・表かプロースか箇条書きかは、そのセッションが素材に合わせて決める。雛形は置かない。固定なのは置き場とファイル名だけ (フックが `CONTEXT.md` を名前で読む) と、冒頭にタスクの一行説明を置くこと。

唯一の要件は、次のセッションの自分が**走査して「これは既に決まっているか」を引ける**形になっていること。

### 残すもの

- **確認した事実と根拠** (ファイルパス:行番号 / URL / 実測値 / node ID)。根拠は、前提が変わったときにどの決定を見直すべきか辿るための唯一の手がかりになる
- **再検証の手順。**手順そのものが資産になる事実は手順まで書く — 根拠の一行だけでは後続が再検証できない
- **決定と理由。**理由は後続が同じ判断を再現できる粒度で。1行で足りなければ段落にする
- **潰した仮説と潰した根拠** (ペアで)。後続が同じ行き止まりを歩くのを防ぐ、最も費用対効果の高い情報。決着済みなら「採らなかった案」として、未決着なら現在地として書く
- **未決着の調査の現在地** — 症状・再現手順・次に見る場所。compact が最も走るのは長い調査の途中で、そこで引き継ぐものが要る。決着したら事実か決定に書き換えて現在地の記述は消す
- **前提と保留事項**

### 残さないもの

- 探索の経路 (どのコマンドを先に打ったか) とツール出力の生ログ。後続で再現不要
- 変更予定ファイル一覧。実装中に変わり陳腐化する
- 撤回された指摘・一過性の訂正。残すと後続が撤回済みの前提で判断する

迷ったら基準は1つ: **後続が同じ作業をやり直さずに済むか。**

**表に押し込むために内容を削らない。** 手順・コード・エラー文・因果の連鎖はセルに入れると潰れる。一覧で走査したいものだけ表にして、あとは本文とコードブロックで書く。書き出しの時点で1行に畳むのも要約であり、禁止 (「追記する」の要約禁止と同じ理由)。

## 読む

注入された記録は**このタスクで確定済み**として扱う。同じ論点を再調査して別の結論に達した場合、記録が古いのではなく自分の再調査が浅い可能性を先に疑う。

**記録の決定と異なる方針を採るときは、実装に入る前に必ず宣言してユーザーの判断を仰ぐ。** 前提が変わったことを確認できたなら、記録を追記してから進める。

## 追記する

決定が変わった時、および新しい事実が判明した時。過去の決定は消さず、変更後の内容と理由を残す (「なぜ変えたか」が後続の判断材料になる)。既存の記録の形に合わせる必要はない — 素材に合わなければ組み替えてよい。

`CONTEXT.md` が上限を超えたら、**撤回・置き換えられた決定**を `CONTEXT.archive.md` へ移す。archive は「もう真ではないもの」の保管先であって、現役の根拠の置き場ではない。注入されないため、現役の情報を移した時点で後続には失われたのと同じになる。撤回済みを出してもまだ超える場合に限り現役の詳細も移せるが、**`CONTEXT.md` 側に「詳細は archive の <節名>」というポインタを必ず残す** (ポインタが無いと後続は archive を読む理由に気づけない)。

**要約による圧縮は禁止。** 選択肢は「archive へ移す」か「そのまま残して上限超過を受け入れる」の2つだけで、要約して1行に畳むのは選択肢に入らない。要約は根拠を落とし、このプラグインが防ごうとしている compact と同じ失敗になる。**現役かどうか判断がつかないものは残す側に倒す。**

上限は分量の強制上限ではなく、記録が決定記録からログへ変質したことを知らせる警報として置いてある。
