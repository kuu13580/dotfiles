# readable-writing

人が読む文章の構成と情報の並べ方の原則集 skill。上の層だけで概要がわかり、詳細は必要なときに引ける形に組み立てる。言い回しは `remove-ai-tone` に任せ、こちらは構成を担当する(remove-ai-tone が効かない場面向けに、言い回しの最低限だけを持つ)。

## いつ発動するか

- PR description、README、報告・進捗・調査結果、手順書、設計書・仕様書、ドキュメントのページ、artifact、チャットへの投稿文を書く・直すとき
- セッションの長い出力(完了報告・調査結果)を書くとき

数行の返答、コミットメッセージ、コードコメントには使わない。

## 仕組み

1. **文脈を判定する**: 目的(判断 / 把握 / 実行 / 後で引く / 理解)、読み手、読まれ方、媒体の性質(図・表・折りたたみが使えるか、長さの上限、ターン制の対話か)
2. **必要な reference だけを読む**: `principles.md` は常に読み、目的別の reference は1つだけ読む。ターン制の対話なら `conversation.md` も読む
3. **既存の文書を書き直すとき**: 中身は変えず、並べ方と言い回しだけを変える。食い違いは「要確認」として残す

優先順位は「ユーザーの指示 > 既存のテンプレート・慣習・CLAUDE.md > この skill」。テンプレートの見出しは変えず、中の並べ方にだけ使う。

| ファイル | 中身 |
| --- | --- |
| `SKILL.md` | 文脈の判定、優先順位、原則の読み方、読むファイルの振り分け、受付箱の運用 |
| `references/principles.md` | どの文章でも使う原則。ツール名を書かず単体で読める形にしている(Gemini などでも使う) |
| `references/purpose/*.md` | 目的別の原則と、文書の種類ごとの並び順(decision / report / procedure / reference / explain) |
| `references/conversation.md` | ターン制の対話(セッション・チャット)だけの原則 |

## セッション出力への適用

skill は毎ターン発動しないため、普段の返答に効かせたいルールはグローバル CLAUDE.md に数行置く。例:

```markdown
## 人が読む文章
- 人に渡す文章(PR description・README・報告・ページ・artifact・チャットへの投稿・長い出力)を書くときは readable-writing skill を使う
- 返答は1ターンに1論点。確認は1件にし、結論と選択肢を先頭に置く
- 選択肢ごとの違い・推奨の理由・検討して退けた案は1行ずつ書く。出典・調査の過程・経緯の詳細は聞かれたら出し、長ければ artifact に置く
- ユーザーが文章の構成を直したら、聞かずに ~/.claude/readable-writing/inbox.md に候補として書く
```

## 受付箱(直しを溜める)

作業中にユーザーが文章の構成を直した・却下したとき、その直しが skill にない(または逆)なら、Claude は聞かずに `~/.claude/readable-writing/inbox.md` に候補として書く。候補は採用されるまで使わない。

正式な reference への取り込みは、このリポジトリで「受付箱を取り込んで」と頼む。候補を採用・不採用・保留の案と理由付きの1つの表にして、採否をまとめて聞き、採用分を reference に移す。受付箱の「出典」行は reference に移さない。

## 意図的に入れていないもの

| 種類 | 理由 |
| --- | --- |
| 文書のテンプレート(節の名前と順序の固定) | 文書の中身に合わない節や無理な分け方が生まれる。塊の役割を例として示すだけにしている |
| 文書の状態と時点の行(進行中・完了など) | 更新されずに陳腐化しやすい |
| 言い回しの細則 | `remove-ai-tone` の担当。最低限の4行だけ持つ |
