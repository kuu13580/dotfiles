# 後で引いてもらう文章

読む場面: README・仕様書・ナレッジ・合意後の設計書など、必要なときに読み手が引いて読む文章を書くとき。`principles.md` に加えて使う。

## 上の層に置く塊の例

塊の役割の例で、この名前や順序を強制しない。該当しない塊は置かない。

- 何のための文書か(1〜2行)
- 一覧(項目と1行の説明の表)
- 決定事項

## 原則

### 見出しには、読み手が探すときに使う語を入れる
理由: 引いて読む文書は、検索や目次から目的の箇所に飛んで読まれる。書き手の分類名では見つからない。
例: 「認証モジュール」ではなく「ログイン状態を保つ仕組み(refresh token)」。

### 1つの項目は、前後を読まなくても分かるように書く
理由: 引いて読む読み手は、目的の項目だけを読む。前の節の説明を前提にすると、その項目だけでは意味が通らない。
例: 「上記の方式では」ではなく「refresh token を使う方式では」と書く。

### 今の仕様と、経緯や過去の仕様を分ける
理由: 混ざっていると、読み手は今も有効な記述かどうかを判断できない。
例: 経緯は「経緯」の節か折りたたみに置き、本文は今の仕様だけにする。

### 一覧は表にし、引きやすい順に並べる
理由: 引いて読む読み手は、一覧から目的の項目を探す。
例: 名前順、またはカテゴリごとに並べる。
