# 理解してもらう文章

読む場面: 解説・設計の説明・仕組みの紹介など、読み手に仕組みや考え方を理解してもらう文章を書くとき。`principles.md` に加えて使う。

## 上の層に置く塊の例

塊の役割の例で、この名前や順序を強制しない。該当しない塊は置かない。

- 全体像の図(一枚絵)
- 何が分かれば読み終えてよいか
- 要点(3〜5個)

## 並び順は、読み手が最初に確かめたいことから決める

| 文書の種類 | 先に置くもの |
| --- | --- |
| 設計の説明 | 概要と全体の図、次に決定事項、その後に仕様と内部設計 |
| 変更の解説 | 変更が乗る既存の仕組み、次に何が変わったか |
| 仕組みの紹介 | 何のための仕組みか、全体の図、その後に各部分 |

## 原則

### 全体像を先に示し、部分の説明はその後に置く
理由: 全体のどこに当たるかが分からないまま部分を読むと、読み手は位置づけを推測しながら読むことになる。

### 説明に必要な前提知識は、本題より前に置く
条件: 読み手の前提知識=ない、または一部ある ／ 理由: 前提を知らないまま本題を読むと、途中で止まって前提を探しに行くことになる。
例: 変更の解説なら、変更が乗る既存の仕組みを先に説明する。説明するのは、変更を理解するのに要る範囲だけにする。

### 抽象的な説明には、具体例を1つ添える
理由: 抽象的な説明だけでは、読み手は自分の場面に当てはめられない。
