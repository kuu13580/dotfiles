# 判断してもらう文章

読む場面: 確認・提案・比較・レビュー依頼・合意を取る前の設計書など、読み手に何かを決めてもらう文章を書くとき。`principles.md` に加えて使う。

## 上の層に置く塊の例

塊の役割の例で、この名前や順序を強制しない。該当しない塊は置かない。

- 結論または推奨
- 決めること(選択肢と、選択肢ごとの違い)
- 退けた案
- 注意
- 後で扱うこと(未決事項・後で聞くこと)

## 並び順は、読み手が最初に確かめたいことから決める

| 文書の種類 | 先に置くもの |
| --- | --- |
| 不具合を直す変更のレビュー依頼 | 症状と原因、修正後の確認方法 |
| 機能を足す・変える変更のレビュー依頼 | 仕様やデザインの資料、利用者から見て変わること |
| 挙動を変えないリファクタリングのレビュー依頼 | 挙動が変わらないことと、変わる箇所があればその理由 |
| 合意を取る前の設計書 | 未決事項、次に決定事項 |

## 原則

### 決めてもらう事項は、件数と一緒に先に示す
理由: 件数が分かれば、読み手はどこまで読めば判断を終えられるか分かる。
例: 「未決事項(5件)」。

### 推奨があるなら、推奨の選択肢を先頭に置いて推奨と書く
理由: 読み手は推奨を基準に他の案と比べられる。

### 選択肢は互いに重ならないようにし、選んだ後に何が起きるかを書く
理由: 選択肢が重なっていたり、選んだ結果が分からなかったりすると、読み手は選べずに聞き返す。

### 決める期限と、決める人を書く
条件: 期限や決める人が決まっているとき ／ 理由: 誰がいつまでに決めるかが分からないと、判断が止まる。
